# 07 · 监控与运维 — CloudWatch / CloudTrail / Config / Systems Manager

> "**谁做了什么?**" → CloudTrail。  
> "**资源状况怎样?**" → CloudWatch。  
> "**配置合不合规?**" → Config。  
> "**怎么远程操作?**" → Systems Manager。

## 一、CloudWatch — 监控与日志

### 三大组件

| 组件 | 一句话 |
|------|--------|
| **Metrics** | 时间序列数据(CPU、磁盘、自定义) |
| **Logs** | 应用 / 系统日志 |
| **Alarms** | 监控 metric 越界 → 触发 SNS / Auto Scaling |

### Metrics 关键概念

| 概念 | 说明 |
|------|------|
| **Standard Resolution** | 60 秒粒度,免费 |
| **High Resolution** | 1 秒粒度,**收费**,适合关键应用 |
| **Custom Metrics** | 应用埋点,通过 SDK / agent 上报 |
| **Detailed Monitoring** | EC2 默认 5 分钟;开启后 1 分钟 |
| **Metric Filter** | 从日志里提取数字作为 metric(如 ERROR 出现次数)|
| **Metric Math** | 对多个 metric 算术(如错误率 = 4xx / total)|

### Logs 关键概念

| 概念 | 说明 |
|------|------|
| **Log Group** | 一组 Log Stream(如某个 Lambda 函数) |
| **Log Stream** | 单一来源(如某个容器实例) |
| **Subscription Filter** | 实时把日志流到 Kinesis / Lambda / Firehose |
| **Logs Insights** | SQL-like 查询语言,临时分析 |
| **Live Tail** | 实时查看日志(2023 新增) |

### 题目套路

| 题目说 | 答案 |
|--------|------|
| "EC2 把内存使用率上报" | **安装 CloudWatch Agent**(内存不是默认 metric) |
| "Lambda 错误率监控并告警" | CW Metric `Errors` + Alarm + SNS |
| "应用日志中"ERROR"出现 5 次 / 5 分钟告警" | **Metric Filter** → 自定义 metric → Alarm |
| "实时把日志送到 OpenSearch" | **CloudWatch Logs Subscription Filter** → Kinesis Data Streams / Firehose → OpenSearch |
| "长期归档应用日志" | Logs → **export to S3** 或直接 Firehose → S3,并设 lifecycle |

### Alarms 状态

- `OK` / `ALARM` / `INSUFFICIENT_DATA`
- **Composite Alarm**:多个 alarm AND/OR 组合,减少误报

## 二、CloudTrail — 谁做了什么

### 三种事件类型

| 类型 | 默认开启 | 说明 |
|------|----------|------|
| **Management Events** | ✅ | 控制台 / API 调用(如 RunInstance、CreateBucket) |
| **Data Events** | ❌(要付费开)| 数据级(S3 object read/write、Lambda invoke) |
| **Insights Events** | ❌ | ML 检测异常 API 活动 |

### 关键考点

- **默认保留 90 天**(在 CloudTrail 控制台 Event History)。要更久 → **新建 Trail** 把事件送到 **S3**。
- **多 Region Trail**:一个 trail 收集**所有 Region** 的事件,**强烈推荐**。
- **Organizations Trail**:在 Management Account 启用,**收集所有成员账号**,成员无法关闭。
- 题目说"防止账号管理员删 trail / 隐藏行迹" → **Organizations Trail + S3 Object Lock** + CloudTrail log file validation。

### CloudTrail vs CloudWatch — 易混

| 维度 | CloudTrail | CloudWatch |
|------|------------|------------|
| 数据 | API 调用 / 审计 | 性能 metric / 日志 |
| 关键问题 | "谁 / 什么时候 / 做了什么" | "状况怎么样" |
| 题目关键词 | **audit、who、API call、compliance** | **CPU、metric、threshold、alarm** |

## 三、AWS Config — 配置合规

### 核心概念

```
   Resource 状态变化
        │
        ▼
   Configuration Item(快照)
        │
   ┌────┴──────┐
   ▼           ▼
 Timeline    Rules (评估合规)
            (managed / custom)
            ┌──────────────┐
            ▼              ▼
        Compliant      Non-compliant
                           │
                           ▼
                     Remediation(自动修复,SSM Automation)
```

### 关键能力

| 能力 | 一句话 |
|------|--------|
| **Configuration History** | 每次资源变化的快照,任意时间点查询 |
| **Conformance Pack** | 一组规则模板(PCI、HIPAA、CIS)|
| **Aggregator** | 跨账号 / Region 集中合规视图 |
| **Auto-Remediation** | 不合规自动修(关联 SSM Automation 文档)|

### 题目套路

| 题目说 | 答案 |
|--------|------|
| "检查所有 S3 桶是否启用了加密" | **Config Rule**(managed: `s3-bucket-server-side-encryption-enabled`)|
| "自动修复:S3 桶被设为 public 时关掉" | Config + **SSM Automation** |
| "跨账号合规仪表板" | **Config Aggregator** |
| "证明在过去某时刻资源 X 的状态" | **Config Timeline** |

### CloudTrail vs Config — 易混(超高频)

| 维度 | CloudTrail | Config |
|------|------------|--------|
| 关心 | **动作**(谁调了 API)| **状态**(资源当下长什么样)|
| 时序 | 事件流 | 状态快照 + 历史 |
| 题目关键词 | who、API、audit | configuration、compliant、changed |

## 四、Systems Manager(SSM)— 运维瑞士军刀

### 必背组件

| 组件 | 一句话 | 何时考 |
|------|--------|--------|
| **Parameter Store** | 配置参数(纯文本或 SecureString) | 题目说"存配置 / API key,免费" |
| **Secrets Manager** | 凭证 + **自动轮换** | 题目说"DB 密码自动轮换" |
| **Session Manager** | 浏览器 / CLI **登录 EC2,无需 SSH/22 端口** | 题目说"私有子网 EC2 不开 22,要登录" |
| **Run Command** | 在数千台 EC2 同时跑脚本 | 批量补丁、运维命令 |
| **Patch Manager** | 自动补丁 | OS 补丁合规 |
| **Automation** | 运维 runbook(YAML 流程) | 自动修复、定期任务 |
| **State Manager** | 把实例拉回期望状态 | 持续合规 |
| **Inventory** | 软件清单 | 资产管理 |
| **OpsCenter** | 集中运维问题面板 | — |

### Parameter Store vs Secrets Manager

| 维度 | Parameter Store | Secrets Manager |
|------|-----------------|-----------------|
| 价格 | **免费**(SecureString 用 KMS 收 KMS 费) | **付费**($0.4/secret/月) |
| 自动轮换 | ❌(自己写) | ✅ **内置 RDS / Redshift / DocumentDB** |
| 跨账号共享 | ✅ | ✅ |
| 复制到其他 Region | ❌ | ✅ |
| 容量上限 | 标准 4 KB,高级 8 KB | 64 KB |

**陷阱**:题目说"**RDS 密码自动每 30 天轮换**" → **Secrets Manager**(不是 Parameter Store)。

### Session Manager — 必背场景

- **私有子网** EC2,**无 22 端口**,**无 bastion host**,通过控制台/CLI 登录
- 不需要 SSH key,审计 / 日志可送到 CloudWatch / S3
- 题目关键词:**"no inbound port"、"no SSH key management"、"audit logging"**

## 五、Trusted Advisor — 自动巡检

5 个维度免费 / Premium 全开(Business 以上):

- 成本优化
- 性能
- 安全(MFA、Open Security Group)
- 容错(Multi-AZ?)
- 服务限制(Service Quota)

题目说"自动检查是否有公网 22 端口 / 未开 MFA 用户" → **Trusted Advisor**(也可以 Config / Inspector)。

## 六、AWS Health Dashboard

- **Service Health**:AWS 全局服务状态(所有用户都看得到)
- **Personal Health**(原 Personal Health Dashboard):**只影响你账号的事件**(维护、计划性中断)
- 可以 EventBridge 触发 Lambda 自动响应

## 七、综合监控架构 — SAA 经典图

```
应用日志 ── CloudWatch Agent ──→ CW Logs
EC2 metric ── 默认 ──→ CW Metrics
API 调用 ──→ CloudTrail ──→ S3 + Athena 查
资源状态 ──→ Config ──→ Aggregator
            │
            ├──→ Alarm ──→ SNS ──→ Email / Lambda / ASG
            │
            └──→ EventBridge ──→ 自动化(Step Functions / SSM)
```
