# 10 · 成本优化 — 把每一分钱花在刀刃上

> Domain 4 占 20%。**几乎每道题都隐含"最便宜"的修饰词**,这章把所有省钱杠杆梳理一遍。

## 一、计算成本 — 关键杠杆

(详见 [`05-计算服务选型.md`](05-计算服务选型.md))

| 杠杆 | 最大节省 | 何时用 |
|------|---------|--------|
| **Spot Instances** | **90%** | 容错任务、Worker、CI |
| **Savings Plans** | 72% | 稳定的长期负载 |
| **Reserved Instances** | 72% | 同上,但绑死实例族 |
| **Graviton(ARM)** | 20-40% | 兼容 Linux 应用,**几乎免费的午餐** |
| **Right-sizing** | 看情况 | Compute Optimizer 推荐 |
| **Auto Scaling 缩容** | 看情况 | 夜间 / 非高峰自动减实例 |
| **Stop 非生产环境** | 全部 | Lambda 调度自动 stop/start |

### Spot 高级用法

| 方法 | 说明 |
|------|------|
| **Spot Fleet** | 多实例族 / 多 AZ 混搭,提高可用性 |
| **Mixed Instance Policy(ASG)** | ASG 内混 On-Demand + Spot,设比例 |
| **Spot Instance Advisor** | 看哪些实例族中断率低 |

## 二、存储成本 — 几个关键决策

### S3 优化

| 杠杆 | 一句话 |
|------|--------|
| **Intelligent-Tiering** | 不知道访问模式时**首选** |
| **Lifecycle Policy** | N 天后转 IA,M 天后转 Glacier,K 天后删 |
| **Storage Lens** | 跨账号 / 跨桶**用量与节省建议** |
| **S3 Analytics** | 看每个桶访问模式,推荐转 IA |
| **Multi-part upload incomplete cleanup** | 设 lifecycle 删除未完成的分段上传(常见隐形成本) |
| **Glacier vs Deep Archive** | 一年内可能要回来 → Glacier;**几乎不回** → Deep Archive |

### EBS 优化

- **gp2 → gp3** 升级(20% 便宜,且 IOPS 独立买)
- 未挂载的 EBS 卷 / 未关联的 EIP **仍然收费** — **Trusted Advisor / Cost Explorer Recommendations** 帮你找
- EBS Snapshot 也按 GB 收(增量,但还是钱)

### 数据传输

| 场景 | 价格 |
|------|------|
| **进入 AWS**(internet → EC2/S3) | **免费** |
| **AZ 之间**(VPC 内同 Region) | $0.01/GB(各方向) |
| **Region 之间** | $0.02/GB+ |
| **AWS 出公网**(EC2 → internet) | $0.09/GB+(头 10 TB) |
| **同 Region 同 AZ**(EC2 ↔ EC2 私有 IP) | 免费 |
| **CloudFront 出公网** | 比 EC2 出公网便宜很多 |

**陷阱**:
- 题目说 "**减少跨 AZ 流量**" → 让应用在**同 AZ 内调用**(用 ALB + zonal target group / Aurora Read Replica 同 AZ)
- 题目说 "**用 CloudFront 省钱**" → 出公网走 CloudFront 比直接 EC2 出便宜
- 题目说 "**S3 Gateway Endpoint**" → 私有访问 S3 **免数据费**(对 NAT 来说能省一大笔)

## 三、Cost 管理工具

| 工具 | 一句话 |
|------|--------|
| **AWS Cost Explorer** | 历史 + 预测 + 推荐 |
| **AWS Budgets** | 设预算,超阈值告警 |
| **AWS Cost Anomaly Detection** | ML 检测异常花费 |
| **Cost & Usage Report (CUR)** | 最细粒度账单 → S3 → Athena 分析 |
| **Trusted Advisor**(成本部分)| 闲置资源、低利用率 |
| **Compute Optimizer** | EC2 / EBS / Lambda / ASG 大小建议 |
| **Savings Plans Recommendations** | Cost Explorer 推荐买哪个 SP |

### 题目套路

| 题目说 | 答案 |
|--------|------|
| "**月底前**收到花费告警" | **AWS Budgets**(可绑 SNS) |
| "意外的费用尖峰自动检测" | **Cost Anomaly Detection** |
| "细到每个标签的成本分析" | **Cost Allocation Tags** + Cost Explorer |
| "EC2 right-size 建议" | **Compute Optimizer** |
| "公司总账单分摊到各部门" | **Organizations + Cost Allocation Tags + CUR** |

## 四、数据库 / 缓存 成本

| 杠杆 | 一句话 |
|------|--------|
| **Aurora Serverless v2** | 间歇负载省成本(秒级缩到 0.5 ACU) |
| **Aurora I/O-Optimized** | 高 I/O 量时比标准便宜(无 I/O 费用) |
| **DynamoDB On-Demand vs Provisioned** | 稳定 → Provisioned + Reserved Capacity 省 60% |
| **RDS Reserved** | 1/3 年承诺 |
| **DynamoDB Global Tables** | 跨 Region 写入,**注意请求加倍计费** |
| **ElastiCache Reserved** | 长期缓存 |

## 五、监控 / 日志成本

- **CloudWatch Logs** 按摄入量收费,**长期保留转 S3** + Lifecycle 转 Glacier
- **VPC Flow Logs** 同上,巨量,选择性开启
- **X-Ray** 按 trace 收费,**采样率**可调
- **CloudTrail Data Events** 不是默认开启,小心额外计费

## 六、设计原则:从一开始就考虑成本

### "最便宜" vs "最高性能" 的平衡

很多 SAA 题目同时要求"成本最低"和"高性能"。**通常答案是**:
- 计算 → **Lambda / Fargate**(按用量)
- 存储 → **S3 + 合适存储类**
- 数据库 → **Aurora Serverless** 或 **DynamoDB On-Demand**
- 流量 → **CloudFront / Gateway Endpoint**

### "成本 + 弹性"

题目说 "**应对突发流量但平时空闲**" → Serverless 三件套(Lambda + DynamoDB + API GW)+ CloudFront

### "成本 + 容错"

题目说 "**批处理任务,容忍中断,最便宜**" → **Spot + Batch / Fargate Spot**

## 七、Free Tier 高频考点

- EC2 t2.micro / t3.micro **750 小时 / 月,12 个月**
- S3 5GB / 20K GET / 2K PUT,12 个月
- Lambda **永久免费 1M 调用 / 400K GB-秒 / 月**
- DynamoDB **永久免费 25 GB / 200M 请求**
- CloudFront 1 TB / 月,12 个月

(SAA 较少考 Free Tier,但偶尔会出现)
