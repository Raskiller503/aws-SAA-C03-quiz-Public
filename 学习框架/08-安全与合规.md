# 08 · 安全与合规 — IAM / KMS / WAF / Shield / GuardDuty / Inspector / Macie

> **Domain 1 占 30% 权重,SAA 第一大主题**。这一章先深入 IAM,再串联 9 个安全服务。

## 一、IAM 深入

### 1.1 Policy 评估逻辑(必背)

```
有 explicit DENY?  ──→ 拒绝
       │
       ▼ no
SCP 允许?(成员账号)  ──→ no → 拒绝
       │
       ▼ yes
Permission Boundary 允许?  ──→ no → 拒绝
       │
       ▼ yes
Session Policy 允许?  ──→ no → 拒绝
       │
       ▼ yes
Identity Policy / Resource Policy 有 ALLOW?  ──→ no → 隐式拒绝
       │
       ▼ yes
   → 允许
```

**口诀**:**显式拒绝总赢;没有显式允许 = 隐式拒绝。**

### 1.2 五种 Policy 类型

| 类型 | 附加在 | 用途 |
|------|--------|------|
| **Identity-based** | User / Group / Role | 给身份什么权限 |
| **Resource-based** | S3 桶 / SQS / SNS / KMS 等 | 谁能访问这个资源 |
| **Permission Boundary** | User / Role | **上限**,即使 identity policy 给了也不能超过 |
| **SCP**(Service Control Policy) | OU / Account | 整个账号的上限 |
| **Session Policy** | STS AssumeRole 临时会话 | 临时缩权 |

### 1.3 IAM Role 关键场景

| 场景 | 配置 |
|------|------|
| EC2 访问 S3 | **Instance Profile**(包装一个 Role) |
| Lambda 访问 DynamoDB | Lambda **Execution Role** |
| 跨账号访问 | A 账号的 Role 设 Trust Policy 信任 B 账号 → B 用户 AssumeRole |
| 联邦企业 AD 登录 AWS | **Identity Center**(原 SSO) + SAML → 自动 AssumeRole |
| Mobile / Web 应用 | **Cognito Identity Pools** → 临时凭证 |

### 1.4 关键工具

| 工具 | 一句话 |
|------|--------|
| **IAM Access Analyzer** | 找出**外部访问**的资源(桶、role、KMS key 等被外人用) |
| **Last Accessed** | 显示 user/role/policy 何时最后使用,**清理过度权限** |
| **Credential Report** | CSV 报告:所有用户的 MFA / 密码 / 密钥状态 |
| **Policy Simulator** | 模拟"这个用户能否调 X API" |

### 1.5 题目套路

| 题目说 | 答案 |
|--------|------|
| "EC2 上的应用要访问 S3,**不要写凭证**" | **IAM Role 附到 EC2**(Instance Profile) |
| "防止开发者把自己 Role 提升到 admin" | **Permission Boundary** |
| "整个 OU 不能开 us-east-2" | **SCP** Deny by `aws:RequestedRegion` |
| "外部用户能不能访问我们的 S3?" | **IAM Access Analyzer** |
| "清理过期权限" | **Last Accessed** + 移除策略 |
| "PowerUser 但**不能**改 IAM" | AWS managed `PowerUserAccess` |

## 二、KMS — 加密密钥管理

### Key 类型

| 类型 | 谁管 | 何时用 |
|------|------|--------|
| **AWS Owned Key** | AWS 完全管,你看不到 | 默认 S3 加密(SSE-S3) |
| **AWS Managed Key**(aws/…)| 部分管 | RDS 默认加密 |
| **Customer Managed Key**(CMK)| **你管** | 自定义旋转、跨账号、key policy |

### Symmetric vs Asymmetric

| 用途 | Key 类型 |
|------|----------|
| 加解密**数据**(默认) | Symmetric(AES-256) |
| 数字签名 / 验签 | Asymmetric(RSA / ECC) |
| HMAC | Symmetric HMAC |

### Key Policy + Grants

- **Key Policy**:谁可以用 / 管这把 key(类似 resource policy)
- **Grant**:临时授权一段时间,适合 Lambda / EC2 临时用 key
- **必须**在 Key Policy 里有人有 `kms:*` 才能管它(否则 key 锁死)

### Envelope Encryption(必懂概念)

**为什么**:KMS 单次加密最多 4 KB 数据,大文件用 KMS API 加密会慢且贵。  
**做法**:KMS 生成 Data Key → 用 Data Key 加密大数据 → 把 加密后的 Data Key 和密文一起存。  
**SDK**:Encryption SDK / S3 Client 自动做这件事。

### 题目套路

| 题目说 | 答案 |
|--------|------|
| "证明 AWS 拿不到我的密钥" | **CloudHSM**(自带 HSM 硬件)或 **SSE-C** |
| "跨账号分享加密 snapshot / S3 对象" | **Customer Managed Key** + key policy 给对方账号 |
| "key 每年自动旋转" | CMK **Automatic Rotation**(默认 365 天) |
| "免费 KMS,只是加密" | **AWS Managed Key**(免费查询) |
| "需要严格 FIPS 140-2 Level 3" | **CloudHSM** |

## 三、WAF / Shield — 边界防护

### WAF(Web Application Firewall)

- 部署在 **CloudFront / ALB / API Gateway / AppSync** 前
- 规则:
  - **Managed Rule Groups**(AWS / Marketplace 提供,OWASP Top 10、Bot Control)
  - **Custom Rules**(自己写,基于 IP、URI、header、body、geo、rate-based)
- **Rate-based Rule**:某 IP 5 分钟内 > N 请求 → 拦
- 题目说 "**SQL injection / XSS / OWASP** 防护" → **WAF**
- 题目说 "**应用层 DDoS / API 暴刷**" → **WAF rate-based** + Shield

### Shield 三档

| 档位 | 价格 | 防什么 |
|------|------|--------|
| **Shield Standard** | 免费 | L3/L4 自动防护(SYN flood、UDP reflection)|
| **Shield Advanced** | $3000/月+ | + DDoS 响应团队、保险费用、L7 防护(配合 WAF)、多 Region 攻击聚合 |

### 题目套路

| 题目说 | 答案 |
|--------|------|
| "应用层防 OWASP" | **WAF** |
| "L3/L4 体积型 DDoS,默认就要的" | **Shield Standard**(自动) |
| "高价值业务,需要 24h 响应、SLA 退款" | **Shield Advanced** |

## 四、Network Firewall

- **VPC 级**深度包检测(SNI 检查、URL 过滤、IPS/IDS)
- 用 Suricata 规则
- 比 WAF 更底层(WAF 是 L7,Network FW 是 L3-L7)
- 题目说 "**egress filtering / 出向 URL 白名单**" → **Network Firewall**

## 五、AWS Firewall Manager

- 在 **Organizations** 范围统一管理:
  - WAF 规则
  - Shield Advanced
  - Network Firewall
  - Security Group(发现公开 SG 等)
- 适合多账号集中策略下发

## 六、威胁检测三件套 — GuardDuty / Inspector / Macie

### 一张对照表

| 服务 | 关心什么 | 数据源 | 题目关键词 |
|------|----------|--------|------------|
| **GuardDuty** | **威胁检测**(异常 API、加密货币挖矿、被入侵主机)| CloudTrail、VPC Flow Logs、DNS、EKS 审计、Lambda、RDS | **malicious、threat、anomaly、compromised** |
| **Inspector** | **漏洞扫描**(EC2 / 容器镜像 / Lambda 函数 CVE)| 自动扫,无需 agent(新版)| **vulnerability、CVE、patch** |
| **Macie** | **PII / 敏感数据发现**(S3 中的信用卡、SSN、健康数据)| S3 对象 | **PII、HIPAA、sensitive data** |

### 题目套路

| 题目说 | 答案 |
|--------|------|
| "检测 EC2 是不是被入侵 / 挖矿" | **GuardDuty** |
| "EC2 系统补丁缺失 / CVE 报告" | **Inspector**(也可以 SSM Patch Manager) |
| "S3 里有没有信用卡号" | **Macie** |
| "异常 API 行为(凌晨从陌生 IP 调) | **GuardDuty** |

## 七、Secrets / Certs

| 服务 | 一句话 |
|------|--------|
| **Secrets Manager** | 自动轮换的密钥 / DB 密码 |
| **Parameter Store** | 配置 + 简单密钥(SecureString) |
| **AWS Certificate Manager**(ACM) | **免费**公共证书 + 自动续期(只给 ALB / CloudFront / API GW / Elastic Beanstalk 等 AWS 服务用) |
| **ACM Private CA** | 私有 CA,**收费** |

**陷阱**:
- ACM 证书**不能直接装到 EC2 应用**(只能给 AWS 服务)— 题目里"EC2 上 nginx 用 SSL"答案通常是把 nginx 卸载,改用 ALB + ACM。
- 题目说 "**RDS 密码每 N 天轮换**" → **Secrets Manager**(不是 KMS / Parameter Store)。

## 八、合规与审计

| 服务 | 一句话 |
|------|--------|
| **Artifact** | 下载 AWS 合规报告(SOC、ISO、PCI DSS) |
| **Audit Manager** | 持续审计证据收集,生成报告 |
| **Detective** | GuardDuty 告警后**追根溯源**(关系图) |
| **Security Hub** | **集中**所有安全告警(GuardDuty + Inspector + Macie + WAF + 等)+ 合规评分 |

### 题目套路

| 题目说 | 答案 |
|--------|------|
| "把 GuardDuty / Inspector / Macie 的告警都汇总" | **Security Hub** |
| "GuardDuty 报警后调查根本原因" | **Detective** |
| "合规报告(PCI DSS)" | **Artifact** 下载 |
| "持续追踪合规证据" | **Audit Manager** |

## 九、跨账号 / 跨 Region 安全集中化

```
       Org Management Account
              │
   ┌──────────┼──────────────┐
   ▼          ▼              ▼
GuardDuty   Security      Config
Delegated   Hub Delegated Aggregator
Admin       Admin         (Delegated)
   │          │              │
   └──────────┴──────────────┘
              │
        所有成员账号
```

- **Delegated Administrator** 是关键模式:Management Account 把审计 / 安全权交给某个"安全账号",成员账号自动汇总到该账号。
