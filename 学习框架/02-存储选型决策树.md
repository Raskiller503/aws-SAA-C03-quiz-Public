# 02 · 存储选型决策树

> SAA 至少 1/4 的题在问"用什么存"。掌握这张决策树,你不需要记 50 个参数,只需要做 5 个判断。

## 一、第一性问题:你的数据"长什么样"?

```
                你要存什么?
                    │
   ┌────────────────┼────────────────┐
   │                │                │
对象 (文件、图片、    │            块 (操作系统盘、
日志、备份)          文件 (要 POSIX、       数据库自管文件)
   │                共享文件系统)         │
   ▼                    │                ▼
  S3                    ▼              EBS
                    EFS / FSx          (单 EC2 attach)
```

| 数据形态 | AWS 服务 | 一句话 |
|----------|----------|--------|
| **对象**(任意大小、不需修改中间字节) | **S3** | 互联网级、键值对存储,11 个 9 持久性 |
| **块**(像硬盘,挂载到一台机器) | **EBS** | EC2 的 SSD/HDD 卷 |
| **共享文件**(Linux NFS / Windows SMB) | **EFS / FSx** | 多台机器同时挂载读写 |

## 二、S3 — 最重要的存储服务

### 2.1 存储类别(必背)

```
访问频率              存储类                  最小存储天数    取回成本
高频(每天)         Standard               无              免费(请求另算)
低频但要快          Standard-IA            30 天          按 GB 取回
低频 + 单 AZ        One Zone-IA            30 天          按 GB
未知模式            Intelligent-Tiering    无              自动迁移,小监控费
归档(分钟级取回)   Glacier Instant Retrieval  90 天      ~毫秒
归档(灵活)        Glacier Flexible Retrieval 90 天    分钟–小时
深度归档(便宜)    Glacier Deep Archive   180 天          12 小时
```

### 决策套路

| 题目说 | 答案 |
|--------|------|
| "未知 / 不可预测访问模式,自动省钱" | **Intelligent-Tiering** |
| "30 天后基本不访问,但要快取回" | Standard → 30 天后 **Standard-IA** |
| "数据可重建、不重要" | **One Zone-IA**(便宜 20%,但仅单 AZ) |
| "7 年合规归档,几乎不取回" | **Glacier Deep Archive** |
| "归档但偶尔需要毫秒取回" | **Glacier Instant Retrieval** |
| "用 lifecycle policy 自动转" | Lifecycle Configuration(`Transition` + `Expiration` 动作) |

### 2.2 加密

| 类型 | 缩写 | 谁管密钥 |
|------|------|----------|
| Server-Side, S3-Managed | **SSE-S3** | AWS,默认开启(新桶) |
| Server-Side, KMS-Managed | **SSE-KMS** | 你在 KMS 里管密钥 |
| Server-Side, **Customer**-Provided | **SSE-C** | 你自带密钥 |
| Client-Side | **CSE** | 上传前自己加密 |
| Dual-Layer Server-Side(KMS) | **DSSE-KMS** | 合规级双层加密 |

**陷阱**:
- 题目说"AWS 管密钥但要审计每次使用" → **SSE-KMS**(KMS 调用会进 CloudTrail)
- 题目说"对客户证明 AWS 拿不到密钥" → **SSE-C** 或 **CSE**
- 2023 后新桶默认 SSE-S3 加密,**强制加密**靠 **bucket policy** 拒绝未加密 PUT。

### 2.3 安全控制 — 控制访问的 6 把锁

| 控制 | 范围 | 备注 |
|------|------|------|
| **Bucket Policy** | 桶级 | JSON,可跨账号,常用 |
| **IAM Policy** | 用户/角色级 | 标准 IAM |
| **ACL** | 对象级 | 老古董,新建议关掉 |
| **Block Public Access** | 账号 / 桶 | 强制 "拒绝公开" 总开关 |
| **VPC Endpoint Policy** | 网络入口 | 仅允许某 VPC 访问桶 |
| **Object Ownership** | 桶 | 设置 "Bucket Owner Enforced" 后 ACL 不再生效 |

**SAA 高频题**:
- 题目说"防止任何人意外把桶公开" → **S3 Block Public Access**(账号级)
- 题目说"只允许特定 VPC 访问桶" → **Gateway Endpoint + bucket policy 限制 aws:sourceVpce**
- 题目说"允许另一个账号读" → **Bucket Policy** 加 principal(或两端用 IAM Role + AssumeRole)

### 2.4 数据保护

| 功能 | 一句话 | 何时用 |
|------|--------|--------|
| **Versioning** | 同 key 保留多版本 | 防误删、配合 lifecycle 删旧版 |
| **MFA Delete** | 删除需要 MFA | 防恶意删除 |
| **Object Lock + Compliance Mode** | WORM,任何人(包括 root)在保留期内不能删 | **法规级别合规**,题目里关键词:**immutable**、**WORM**、**SEC 17a-4**、**legal hold** |
| **Object Lock + Governance Mode** | 受限的可删除 | 灵活合规 |
| **Replication(SRR/CRR)** | 同 / 跨 Region 复制 | 灾备、低延迟读 |
| **S3 Replication Time Control(RTC)** | 15 分钟内 99.99% 复制完成 SLA | 题目说"15 分钟以内强一致复制" |

### 2.5 性能优化

| 场景 | 选什么 |
|------|--------|
| 单文件 > 100 MB 上传 | **Multipart Upload** |
| 全球用户上传到单个桶 | **Transfer Acceleration**(走 CloudFront 边缘 → S3) |
| 频繁全球分发 | **CloudFront**(配 OAC) |
| 大量 LIST / 高读取性能 | 设计前缀(不再需要 8 字符随机 hash,S3 已自动扩展) |
| 海量小对象高频写 | **S3 Express One Zone**(2023 新出,单 AZ 个位数毫秒) |

## 三、EBS — EC2 的硬盘

### 卷类型对照(必背)

| 类型 | 类别 | 典型用途 | 关键指标 |
|------|------|----------|----------|
| **gp3** | SSD 通用 | **首选默认**;Web 服务器、boot | 3000 IOPS / 125 MB/s 基线,可独立买更高 |
| **gp2** | SSD 通用 | 老版,大小决定 IOPS | 100–16K IOPS,3 IOPS/GiB |
| **io2 Block Express** | SSD Provisioned IOPS | **关键数据库 / 高 IOPS** | 最高 256K IOPS,**99.999% 持久性** |
| **io1** | SSD Provisioned IOPS | 老版 | 最高 64K IOPS |
| **st1** | HDD 吞吐型 | **大日志、大数据顺序读写** | 不能 boot |
| **sc1** | HDD 冷盘 | **不常访问、便宜** | 不能 boot |

### 关键性质

- **EBS 卷绑定到 1 个 AZ**,EC2 必须同 AZ 才能挂。
- **跨 AZ 迁移**:做 **Snapshot → 复制 → 在另一 AZ 创建卷**。
- **Snapshot 存到 S3**(增量、跨 AZ),**可复制到另一 Region 做灾备**。
- **EBS Multi-Attach**:io1/io2 支持挂到**同 AZ 内多达 16 台**实例(用于集群文件系统,不是普通文件共享)。

### 加密

- **EBS 默认加密**:账号级开关,新卷一律加密。
- **Snapshot 跨账号共享**:加密的 snapshot 不能直接共享 — 必须**先共享 KMS Key**。

## 四、EFS / FSx — 共享文件系统

```
                   多台 EC2 同时读写一份文件?
                         │
            ┌────────────┴────────────┐
            │ Linux NFS              │ Windows SMB
            │                        │  或 高性能并行
            ▼                        ▼
           EFS                    FSx 家族
       (托管 NFS)            ┌─────────┬─────────┬─────────┐
                            FSx for   FSx for   FSx for   FSx for
                           Windows   Lustre    NetApp     OpenZFS
                            (AD/SMB)  (HPC)    ONTAP      (低延迟)
```

| 服务 | 何时选 |
|------|--------|
| **EFS Standard** | Linux NFS,多 AZ 自动同步,弹性扩展 |
| **EFS IA / Archive** | 低频访问降本(配合 Lifecycle Policy) |
| **FSx for Windows File Server** | Windows 应用、Active Directory 集成、SMB |
| **FSx for Lustre** | HPC、机器学习、SageMaker、关联 S3 数据集 |
| **FSx for ONTAP** | 已有 NetApp 体系迁移,多协议(NFS/SMB/iSCSI) |
| **FSx for OpenZFS** | 极低延迟 NFS、快照 / 克隆 |

### 关键考点

- **EFS** 跨 AZ 自动复制(默认),**EBS** 不跨 AZ。
- 多台 EC2 同时挂载读写同一份 → **EFS**(Linux)/ **FSx for Windows**
- 题目说 "**Lustre + S3 数据湖**" → **FSx for Lustre**(可直接读 S3 数据集)

## 五、跨场景对比 — 一张表

| 维度 | S3 | EBS | EFS | FSx |
|------|----|----|----|----|
| 抽象 | 对象 | 块 | 文件 | 文件 |
| 协议 | HTTPS API | 块设备 | NFS v4 | SMB / Lustre / NFS / iSCSI |
| 范围 | Region | 单 AZ | 多 AZ | 单 / 多 AZ(看类型) |
| 持久性 | 11 个 9 | 5–8 个 9(看卷) | 11 个 9 | 11 个 9 |
| 最大 size | 单对象 5TB | 单卷 16 TiB(gp3) | 弹性、PB+ | TB–PB |
| 典型用法 | 静态、日志、备份、数据湖 | EC2 系统盘 / DB | 容器、CMS 共享 | Windows AD、HPC |
| 计费 | 按 GB + 请求数 + 出口 | 按 GB-月 + IOPS(io)| 按 GB-月(冷热分层) | 按 GB-月 |
