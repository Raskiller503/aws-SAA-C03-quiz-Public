# 01 · 架构师的全局视图

> 在学具体服务前,先把"AWS 的地理 / 网络 / 账号"这张大底图画清楚。所有后面的服务都是挂在这张底图上的。

## 一、四层"位置"层级 — 从外到内

```
┌─────────────────────────────────────────────────────────────┐
│ Partition(分区:aws、aws-cn、aws-us-gov)                    │
│ ┌─────────────────────────────────────────────────────────┐ │
│ │ Region(区域:us-east-1, ap-southeast-1, …)              │ │
│ │ ┌──────────────┐ ┌──────────────┐ ┌──────────────┐      │ │
│ │ │ AZ a         │ │ AZ b         │ │ AZ c         │      │ │
│ │ │ ┌──────────┐ │ │ ┌──────────┐ │ │ ┌──────────┐ │      │ │
│ │ │ │  Subnet  │ │ │ │  Subnet  │ │ │ │  Subnet  │ │      │ │
│ │ │ │ (VPC 内) │ │ │ │ (VPC 内) │ │ │ │ (VPC 内) │ │      │ │
│ │ │ └──────────┘ │ │ └──────────┘ │ │ └──────────┘ │      │ │
│ │ └──────────────┘ └──────────────┘ └──────────────┘      │ │
│ │           Edge Locations(CloudFront / Route 53)         │ │
│ └─────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
```

| 层级 | 含义 | 故障域 |
|------|------|--------|
| Partition | 法律 / 监管隔离的 AWS 大区(中国 vs 全球 vs 美国政府)| 完全隔离 |
| Region | 一个城市群,典型有 3–6 个 AZ | 地震 / 全城断电 |
| Availability Zone(AZ) | 一个或多个物理数据中心(同 Region 内) | 单数据中心 |
| Subnet | VPC 切片,**绑定到唯一 AZ** | 网段级 |
| Edge Location | CDN 节点,数百个全球分布 | — |

### 关键考点

- **AZ 之间** 低延迟(< 1ms 通常),走 AWS 骨干网,**Region 内 AZ 间数据传输也收费(免费的是 S3 → 同 Region EC2 这类)** — 多选题里小心。
- **Region 之间** 走加密的 AWS 骨干,但**默认要付出口费**。
- **Edge Locations** 不只是 CloudFront,还托管 Lambda@Edge、Route 53、Global Accelerator、AWS Shield、WAF。

## 二、账户结构 — Organizations

```
        ┌──────────────────────┐
        │  Management Account  │  ← 付款账户,启用 SCP
        └──────────┬───────────┘
                   │
        ┌──────────┴──────────┐
        │   Root OU           │
        │  ┌───────────────┐  │
        │  │  Prod OU      │  │  ← Service Control Policies (SCP)
        │  │   ├─ Acct A   │  │     在这一层批量限制下面账号
        │  │   └─ Acct B   │  │
        │  │  Dev OU       │  │
        │  │   ├─ Acct C   │  │
        │  │   └─ Acct D   │  │
        │  │  Sandbox OU   │  │
        │  │   └─ Acct E   │  │
        └──┴───────────────┴──┘
```

### 必须记住的服务

| 服务 | 一句话 | 题目里见到该选 |
|------|--------|----------------|
| **AWS Organizations** | 多账号集中管理 | 题目说"多个 AWS 账号" |
| **SCP(Service Control Policy)** | OU/账号级"上限"权限策略 | 题目说"防止某账号开 c5.24xlarge"或"阻止某 region" |
| **AWS Control Tower** | 一键搭好 landing zone(Org + 配置基线) | 题目说"快速搭多账号合规基线" |
| **Consolidated Billing** | 合并账单、共享 RI/SP 折扣 | 题目说"统一开票" |
| **AWS IAM Identity Center**(原 SSO) | 跨账号 / 应用 SSO,与 AD / Okta 联邦 | 题目说"统一登录多账号 + 联邦企业目录" |

### SCP 的陷阱

- SCP **不授予权限**,它只是"上限"(deny list / allow list)。**用户实际权限 = IAM 策略 ∩ SCP**。
- SCP **作用于成员账号的 IAM 用户和角色**,**但不作用于 Management Account 的根用户**。
- 题目说"无论账号管理员怎么改 IAM,都不能开某 Region" → SCP。

## 三、VPC — 你的私有数据中心

> VPC 是 SAA 题目里**出现频率最高**的对象之一。强烈建议自己画一遍下面这张拓扑。

```
                 Internet
                    │
            ┌───────┴────────┐
            │ Internet Gateway│
            └───────┬────────┘
                    │
   ┌────────────────┴─────────────────┐ VPC (10.0.0.0/16)
   │                                  │
   │  ┌─────────┐         ┌─────────┐ │
   │  │ Public  │         │ Public  │ │
   │  │ Subnet  │         │ Subnet  │ │
   │  │ (AZ-a)  │         │ (AZ-b)  │ │
   │  │  ┌───┐  │         │  ┌───┐  │ │
   │  │  │ALB│  │         │  │NAT│  │ │  ← NAT Gateway 也要多 AZ 高可用
   │  │  └───┘  │         │  └───┘  │ │
   │  └────┬────┘         └────┬────┘ │
   │       │                   │      │
   │  ┌────┴────┐         ┌────┴────┐ │
   │  │ Private │         │ Private │ │
   │  │ Subnet  │         │ Subnet  │ │
   │  │ (AZ-a)  │         │ (AZ-b)  │ │
   │  │  ┌───┐  │         │  ┌───┐  │ │
   │  │  │EC2│  │         │  │EC2│  │ │
   │  │  └───┘  │         │  └───┘  │ │
   │  └─────────┘         └─────────┘ │
   │                                  │
   │   ┌──────────────┐               │
   │   │ DB Subnet    │  (用于 RDS,  │
   │   │ (Private)    │   两个 AZ)   │
   │   └──────────────┘               │
   └──────────────────────────────────┘
```

### 关键概念区分(SAA 高频考点)

| 概念 | 作用范围 | 状态 | 默认行为 |
|------|----------|------|----------|
| **Security Group**(安全组) | 实例级(ENI 级) | **stateful**(响应自动放行) | 默认拒绝所有入站,允许所有出站 |
| **Network ACL**(NACL) | 子网级 | **stateless**(响应需显式规则) | 默认全放行 |
| **Route Table** | 子网级 | — | 默认仅 VPC 内 local 路由 |

**记忆口诀**:**S**ecurity Group = **S**tateful;**N**ACL = **N**umbered + Stateless。

### VPC 连接方式 — 何时用哪个?

| 需求 | 选择 |
|------|------|
| VPC 内出公网 | Internet Gateway(IGW) |
| 私有子网出公网(单向) | **NAT Gateway**(托管、高可用、贵)/ NAT Instance(自己装,几乎不要选) |
| 私有子网访问 S3/DynamoDB **不走公网** | **Gateway Endpoint**(免费) |
| 私有子网访问其他 AWS 服务(SQS、SNS、KMS…)**不走公网** | **Interface Endpoint / PrivateLink**(按小时 + 数据收费) |
| 两个 VPC 互通,同 / 跨账号 / 跨 Region | **VPC Peering**(点对点,不传递)/ **Transit Gateway**(中心辐射,可传递) |
| 公司机房 ↔ VPC,廉价 / 加密 | **Site-to-Site VPN**(基于 IPsec,几小时上线) |
| 公司机房 ↔ VPC,**稳定低延迟** | **Direct Connect**(物理专线,数周开通) |
| 跨 Region 全球互联 | **Transit Gateway peering** 或 **Cloud WAN** |

**陷阱**:
- 题目说"上线快、低成本、加密" → **VPN**
- 题目说"稳定带宽 + 低延迟 + 不走公网" → **Direct Connect**(若再要求加密 → DX + VPN over DX)
- 题目说"跨多个 VPC 简化路由" → **Transit Gateway**(不是 Peering)
- 题目说"私有访问 S3,无需公网,**免费**" → **Gateway Endpoint**

## 四、IAM 入门(详细见第 8 章)

### 三类身份

```
┌──────────┐   ┌──────────┐   ┌──────────┐
│  User    │   │  Group   │   │  Role    │
│ (长期凭证) │   │ (用户集合) │   │ (临时凭证) │
└──────────┘   └──────────┘   └──────────┘
```

| 选择 | 何时用 |
|------|--------|
| **IAM Role** | 给 **AWS 服务**(EC2、Lambda)用 / **跨账号**访问 / **联邦身份**(SAML、OIDC、SSO) |
| **IAM User** | 真人长期访问 — **越来越少推荐**,SAA 题目里几乎都改用 Role + Identity Center |
| **Group** | 把 User 按职能分组,统一附加 Policy |

### 关键原则

- **最小权限原则(least privilege)** — SAA 经常考"用户能改 IAM 但不该改"的场景,答案多是 **SCP + IAM Permission Boundary** 限制上限。
- **凭证**:**长期** = Access Key(尽量不用);**短期** = STS AssumeRole(推荐)
- **凭证泄露怎么办?** — 立刻 **rotate Access Key**;若用 Role/STS,等过期就失效。
