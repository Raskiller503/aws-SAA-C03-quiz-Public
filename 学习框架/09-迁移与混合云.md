# 09 · 迁移与混合云

> 这章题量不多但**陷阱集中**。重点把"什么场景用什么迁移服务"对清楚。

## 本章先懂这些词

迁移题先判断两件事:迁的是什么,以及迁完后是否还要和本地持续互通。一次性搬数据和长期混合云,答案通常完全不同。

| 术语 | 白话解释 | 常见考法 |
|------|----------|----------|
| **On-premises** | 本地机房/自有数据中心 | 和 AWS 互联、迁移上云 |
| **Hybrid cloud** | 本地和云同时使用 | Storage Gateway、VPN、DX、Outposts |
| **Lift-and-shift / Rehost** | 基本不改应用,整机搬到云上 | MGN |
| **Sync** | 持续或定时同步文件 | DataSync |
| **Offline transfer** | 用物理设备搬数据 | Snowball |
| **NFS / SMB** | 文件共享协议 | Linux 常 NFS,Windows 常 SMB |
| **SFTP / FTPS / FTP** | 文件传输协议 | Transfer Family |
| **iSCSI** | 把远端存储当块设备用 | Volume Gateway |

## 一、上云迁移服务矩阵

```
要迁什么?
   │
   ├─ 整台服务器(VM) ─→ AWS Application Migration Service (MGN)
   ├─ 数据库 ──────────→ DMS(+ SCT 异构 schema)
   ├─ 文件 ─ NFS/SMB ──→ DataSync
   ├─ 大块数据(PB)──→ Snowball / Snowmobile
   ├─ 流式 SFTP/FTPS ──→ Transfer Family
   ├─ 整个应用栈发现 ──→ Application Discovery Service
   └─ 多账号迁移管理 ──→ Migration Hub(顶层 dashboard)
```

## 二、Snow 家族 — 一句话区分

| 设备 | 容量 | 计算? | 何时用 |
|------|------|-------|--------|
| **Snowcone** | **8 TB** HDD / 14 TB SSD | 边缘小计算 | IoT 边缘、单兵带走、小数据 |
| **Snowball Edge Storage Optimized** | **80 TB** | 限定 | 离线传输大量数据 |
| **Snowball Edge Compute Optimized** | 42 TB | EC2 + GPU | 边缘 ML、视频处理 |
| **Snowmobile**(已退役)| 100 PB | — | 数据中心整体搬迁 |

### Snow 题目套路

| 题目说 | 答案 |
|--------|------|
| "100 TB 数据 + 网络很慢" | **Snowball Edge** |
| "小型 IoT 边缘,断网采集" | **Snowcone** |
| "**几个 GB / TB** 数据,网络好" | **不要选 Snow,选 S3 + DataSync / Transfer Acceleration**(Snow 是杀鸡用牛刀) |

## 三、AWS DataSync vs Storage Gateway — 必须分清

| 维度 | DataSync | Storage Gateway |
|------|----------|-----------------|
| 模式 | **一次性 / 调度同步** | **持续混合存储** |
| 协议 | NFS / SMB / HDFS / S3 / EFS / FSx | NFS / SMB / iSCSI / Tape |
| 用途 | 把本地文件**迁到 AWS** | 让本地应用**像本地一样**访问云存储 |
| 关键词 | migrate、sync、transfer | **hybrid、on-premises 持续访问** |

### Storage Gateway 三种类型

| 类型 | 行为 |
|------|------|
| **File Gateway** | 本地通过 NFS/SMB 访问,**后端是 S3** |
| **Volume Gateway**(Cached / Stored) | iSCSI 块设备 — Cached:热数据本地,冷数据在 S3;Stored:全部本地 + Snapshot 到 S3 |
| **Tape Gateway** | 把本地磁带备份程序 **替换为云** → S3 + Glacier |

### 题目套路

| 题目说 | 答案 |
|--------|------|
| "本地 NFS 文件**一次性**迁到 S3" | **DataSync** |
| "本地应用继续用 NFS,数据其实在 S3" | **File Gateway** |
| "本地有备份软件用磁带,想换 cloud" | **Tape Gateway** |
| "VMware 上的服务器迁过来" | **AWS Application Migration Service (MGN)** |
| "数据库 Oracle → Aurora 异构迁移" | **SCT + DMS** |
| "Oracle → Oracle 同构迁移" | **DMS** 直接 |

## 四、AWS Transfer Family

- **SFTP / FTPS / FTP / AS2** 端点,后端 S3 或 EFS
- 用 IAM / AD / 自定义身份验证
- 题目说"客户用 SFTP 上传文件到我们 S3" → **Transfer Family**(不是 DataSync)

## 五、混合云 — 计算与运营

| 服务 | 一句话 |
|------|--------|
| **AWS Outposts** | **AWS 硬件搬到你机房**,跑 EC2/S3/RDS/EKS,**API 一致** |
| **AWS Local Zones** | AWS 在大城市的"小 Region"扩展,低延迟到本地 |
| **AWS Wavelength** | 5G 运营商基站内的 AWS 计算,**极低移动延迟** |
| **VMware Cloud on AWS** | 在 AWS 跑 VMware 集群 |
| **EKS Anywhere / ECS Anywhere** | 在本地 / 多云跑 EKS/ECS 控制 |
| **AWS App Mesh** | Service mesh,跨 EC2/ECS/EKS |

### 题目套路

| 题目说 | 答案 |
|--------|------|
| "受数据驻留法规约束,数据必须留在本地,但还想用 AWS API" | **Outposts** |
| "应用对延迟极敏感(< 10ms),本地城市无 Region" | **Local Zones** |
| "5G 移动游戏 / AR 极低延迟" | **Wavelength** |
| "已有 VMware 投资,想保留 + 上云" | **VMware Cloud on AWS** |

## 六、Application Migration Service (MGN) vs Server Migration Service (SMS)

- **MGN**(新)— 推荐,**lift-and-shift** 服务器(物理 / 虚拟 / VMware / Hyper-V / 云上)整机搬迁
- **SMS** — 旧的,已被 MGN 取代
- 题目说"**lift-and-shift / rehost**" → **MGN**

### 6 R 迁移策略(常考概念)

| 策略 | 一句话 | 工具 |
|------|--------|------|
| **Rehost**(lift-and-shift) | 不改代码搬过来 | **MGN** |
| **Replatform**(lift-tinker-shift) | 小调整(如换 RDS) | **DMS** |
| **Repurchase**(drop and shop) | 换 SaaS | — |
| **Refactor / Re-architect** | 重写为云原生 | CDK / Lambda |
| **Retire** | 退役 | — |
| **Retain** | 暂留本地 | — |

## 七、Application Discovery Service

- 在本地装 agent 或 agentless,**发现服务器、依赖、网络流量**
- 输出给 **Migration Hub** 做计划
- 题目说"我也不知道哪些服务器要迁,先扫一遍" → **Application Discovery Service**
