# 05 · 计算服务选型 — EC2 / Lambda / 容器

> SAA 计算题主要问"在 EC2、Lambda、ECS、Fargate、Batch 之间挑哪个",且常常和**成本 + 弹性 + 运维负担**绑定问。

## 本章先懂这些词

计算服务就是"代码在哪里运行"。选型时先判断你想管到哪一层:自己管虚拟机选 EC2,只交函数选 Lambda,交容器但不管服务器选 Fargate。

| 术语 | 白话解释 | 常见考法 |
|------|----------|----------|
| **Workload** | 一段要运行的业务负载 | Web 服务、批处理、API、定时任务 |
| **Instance** | 一台云上虚拟机 | EC2 的基本单位 |
| **Serverless** | 不直接管理服务器 | Lambda、Fargate、DynamoDB 常见 |
| **Container** | 把应用和依赖打包成镜像运行 | ECS / EKS / Fargate |
| **Launch type** | 容器跑在哪里 | EC2 launch type 自管节点,Fargate 不管节点 |
| **Concurrency** | 同时运行多少个请求/函数 | Lambda 并发题高频 |
| **Cold start** | 函数一段时间没跑,首次启动变慢 | Provisioned Concurrency / SnapStart |
| **IaC** | 用代码描述基础设施 | CloudFormation、CDK、Terraform |

## 一、第一性决策树

```
                你的工作负载?
                       │
   ┌───────────────────┼────────────────────────┐
   │                   │                        │
长期稳定 / 老应用    短小 + 事件触发        容器化
   │                   │                        │
   ▼                   ▼                        ▼
  EC2               Lambda                    ECS / EKS
                                    ┌──────────┴──────────┐
                                    │                     │
                                  Fargate              EC2 launch type
                              (无服务器容器)         (自管节点)
```

## 二、EC2 实例族 — 不用背全部

只要记**字母前缀**:

| 字母 | 含义 | 何时选 |
|------|------|--------|
| **M** | General(通用) | 默认选项,Web / 应用服务器 |
| **C** | Compute optimized | CPU 密集:批处理、编码、机器学习推理 |
| **R** | Memory optimized | 内存数据库、内存分析 |
| **X / z** | 大内存 | SAP HANA、大型内存数据库 |
| **I / D** | Storage(SSD/HDD)| NoSQL、Hadoop、本地高 IOPS |
| **P / G / Inf / Trn** | GPU / 加速器 | 机器学习、图形 |
| **T** | Burstable(突发) | 间歇负载,基线 + 突发额度,**便宜**;**长期跑满会被节流** |
| **A** | Graviton(ARM) | **20%–40% 性价比**,新选择 |

数字后缀(t2 → t3 → t4g):**越大越新**,几乎总是用最新一代更省钱。

### 题目套路

| 题目说 | 答案 |
|--------|------|
| "便宜 + ARM + 兼容 Linux" | Graviton(**a / g** 系列,如 m6g、t4g) |
| "突发 CPU,平时低负载" | **T 系列**(t3 / t4g) |
| "高内存数据库" | **R / X / z** 系列 |
| "高 IOPS 本地 NVMe" | **I 系列** + Instance Store |
| "GPU 训练" | **P / Trn**(训练专用) |
| "GPU 推理" | **G / Inf** |

## 三、EC2 计费模式 — 必背

| 模式 | 折扣 | 承诺 | 何时用 |
|------|------|------|--------|
| **On-Demand** | 0 | 无 | 短期、不稳定,刚搭建 |
| **Savings Plans**(Compute / EC2 / SageMaker) | 最高 72% | 1/3 年承诺 $/小时 | **首选**,涵盖 EC2/Lambda/Fargate |
| **Reserved Instances** | 最高 72% | 1/3 年承诺**特定实例族 + Region** | 老办法,新项目用 Savings Plans |
| **Spot** | 最高 90% | 无,**可被回收**(2 分钟通知) | **容错任务**:批处理、CI、ML 训练、无状态 web |
| **Dedicated Host** | — | 物理机隔离 | License 绑定(Windows、Oracle) |
| **Dedicated Instance** | — | 物理隔离但不需要主机可见性 | 合规要求 |
| **Capacity Reservations** | 0 | 预留容量,**保证可用** | 重要任务,即使不打折 |

### Savings Plans 三个 flavor

| 类型 | 范围 | 折扣 |
|------|------|------|
| **Compute Savings Plan** | **最灵活**:跨 EC2/Lambda/Fargate,任意 Region/实例族 | 最高 66% |
| **EC2 Instance Savings Plan** | 锁定实例族 + Region | 最高 72% |
| **SageMaker Savings Plan** | SageMaker 实例 | — |

### 题目套路

| 题目说 | 答案 |
|--------|------|
| "可容忍中断、便宜" | **Spot** |
| "稳定 3 年负载,最大折扣" | **EC2 Instance SP**(3 年 + all upfront) |
| "Lambda + Fargate + EC2 都想打折" | **Compute Savings Plan** |
| "BYOL Windows / Oracle" | **Dedicated Host** |
| "保证有容量但不需折扣" | **On-Demand Capacity Reservation** |

## 四、Spot Instances 深入

### 中断行为

- **2 分钟通知**(via instance metadata + EventBridge)
- 中断后:Stop / Hibernate / Terminate(可配置)
- **Spot Fleet** / **Spot Block**(已弃)/ **EC2 Fleet**:混搭 Spot + On-Demand

### 适合 / 不适合

| 适合 | 不适合 |
|------|--------|
| 无状态 web(配合 ASG + ALB) | 单点数据库主节点 |
| 批处理、CI、视频转码 | 长事务、不可恢复任务 |
| ML 训练(checkpoint) | 短临时但绝对不能中断 |
| 容器 Worker(EKS/ECS) | — |

## 五、Lambda — 函数即服务

### 关键限额(必背 — SAA 高频)

| 限额 | 值 |
|------|---|
| 单次执行最长 | **15 分钟** |
| 内存 | 128 MB – 10,240 MB |
| /tmp 临时空间 | **512 MB – 10,240 MB**(可配) |
| 部署包(zip)| 50 MB(直传)/ 250 MB(unzip)|
| 镜像 | **最大 10 GB** |
| 并发(账号 / Region) | 默认 1000,可申请提高 |
| 环境变量 | 4 KB |
| Payload(请求 / 响应) | 同步 6 MB / 异步 256 KB |

### 触发器分类

| 类型 | 例子 |
|------|------|
| 同步 | API Gateway、ALB、Cognito |
| 异步 | S3 事件、SNS、EventBridge |
| 流 / Poll | DynamoDB Streams、Kinesis、SQS、MSK |

### 并发控制

| 概念 | 说明 |
|------|------|
| **Reserved Concurrency** | 锁定该函数最多 N 并发 |
| **Provisioned Concurrency** | **预热 N 个实例**,消除冷启动 |
| **Lambda SnapStart**(Java)| 启动时间从秒级到毫秒级 |

### 题目套路

| 题目说 | 答案 |
|--------|------|
| "处理时间 < 15 分钟、按调用付费" | **Lambda** |
| "处理时间 > 15 分钟 / 长任务" | **Fargate** / **Batch** / **ECS** |
| "Lambda 第一次响应慢(冷启动)" | **Provisioned Concurrency**(或 SnapStart 对 Java) |
| "Java Lambda 冷启动" | **SnapStart** |
| "Lambda 想用大临时空间" | **/tmp 提高到 10 GB**(2022 新增) |
| "Lambda 容器镜像" | 镜像可达 **10 GB**(zip 仅 250 MB) |

## 六、容器服务 — ECS / EKS / Fargate

### 矩阵

|  | 控制面 | 数据面(节点) |
|---|--------|---------------|
| **ECS on EC2** | AWS 托管 ECS | 你自管 EC2 |
| **ECS on Fargate** | AWS 托管 ECS | **AWS 托管,无服务器** |
| **EKS on EC2** | AWS 托管 K8s API | 你自管 EC2 |
| **EKS on Fargate** | AWS 托管 K8s API | **AWS 托管,无服务器** |

### 选择套路

| 题目说 | 答案 |
|--------|------|
| "无 Kubernetes 经验、AWS 原生" | **ECS** |
| "已有 Kubernetes / 多云迁移" | **EKS** |
| "完全无服务器、不想管节点" | **Fargate**(配 ECS 或 EKS) |
| "需要 GPU + 高度定制" | **EC2 launch type** |
| "Lambda 容器但要超过 15 分钟" | **Fargate** |

### App Runner

- 一行命令把容器变成生产 URL,**完全托管**
- 比 Fargate 更简化,适合 "PaaS 风格" 微服务
- 题目说"最少配置部署容器化 Web 应用 + HTTPS + 自动扩展" → **App Runner**

## 七、批处理 — AWS Batch

- 用于**大规模容器化批任务**调度
- 可跑在 EC2 / Fargate / Spot
- 自动算需要多少机器、跑完释放
- 题目说"科学计算 / 视频转码批量任务" → **AWS Batch**(配 Spot)

## 八、Elastic Beanstalk vs CloudFormation vs SAM vs CDK

| 工具 | 抽象层级 | 何时用 |
|------|----------|--------|
| **Elastic Beanstalk** | 一键部署 web 应用,**底层 EC2+ASG+ELB+RDS** | 想快速上线 + 不想管基础设施 |
| **CloudFormation** | IaC,YAML/JSON 描述 stack | **AWS 原生 IaC 首选** |
| **SAM**(Serverless Application Model)| CloudFormation 的 serverless 简化版 | Lambda / API GW 应用 |
| **CDK**(Cloud Development Kit)| 用 Python/TS/Java 写 IaC,最终编译成 CFN | 程序员友好的 IaC |
| **Terraform** | 第三方,跨云 | 多云环境 |

### 题目套路

| 题目说 | 答案 |
|--------|------|
| "把代码丢给 AWS,自动起 web 应用" | **Elastic Beanstalk** |
| "IaC,AWS 原生" | **CloudFormation** 或 **CDK** |
| "Serverless 应用 IaC,简化" | **SAM** |
| "跨 AWS / Azure 的 IaC" | **Terraform** |

## 九、Step Functions — 工作流编排

- 把多个 Lambda / ECS / Batch / 等服务串成状态机
- **2 种类型**:
  - **Standard**:最长 1 年,**精确一次**,贵
  - **Express**:最长 5 分钟,**至少一次**,**100K/秒**,便宜
- 题目说"长流程、可视化、错误重试" → **Step Functions**
- 题目说"高 QPS 短流程(IoT、事件处理)" → **Step Functions Express**
