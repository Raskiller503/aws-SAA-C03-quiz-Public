# 04 · 网络架构 — ELB / Route 53 / CloudFront / VPC 进阶

> 网络题不一定难,但**陷阱密集**。这章把 ELB 三件套、Route 53 七种路由、CloudFront 与全球加速、VPC 高级互联放在一起。

## 本章先懂这些词

网络题的核心是"流量从哪里来,要到哪里去,中间经过谁"。初学者先把公网入口、负载均衡、DNS、缓存、私网互联分开,不要把它们都混成"网络服务"。

| 术语 | 白话解释 | 常见考法 |
|------|----------|----------|
| **DNS** | 把域名解析成地址 | Route 53 |
| **Load Balancer** | 把流量分给多台后端 | ALB/NLB/GWLB |
| **L7** | 应用层,看得懂 HTTP 路径和 Header | 路径路由、Host 路由选 ALB |
| **L4** | 传输层,主要看 TCP/UDP 连接 | 静态 IP、极低延迟、UDP 选 NLB |
| **CDN** | 把内容缓存到离用户近的边缘节点 | CloudFront |
| **Origin** | CDN 回源的真实后端 | S3、ALB、EC2、自定义服务器 |
| **Health Check** | 定期探测后端是否健康 | 故障切换和负载均衡都常用 |
| **Static IP** | 固定不变的 IP | 常指向 NLB 或 Global Accelerator |

## 一、ELB(Elastic Load Balancer)三件套

```
                      你的流量是?
                            │
   ┌────────────────────────┼─────────────────────────┐
   │                        │                         │
HTTP/HTTPS              TCP/UDP                  极致性能
(L7,7 层)              (L4,4 层)               (低延迟)
   │                        │                         │
   ▼                        ▼                         ▼
  ALB                      NLB                       GWLB
  Application LB           Network LB                Gateway LB
                                                    (穿透 3rd-party 设备)
```

### ALB(Application Load Balancer)

| 特性 | 说明 |
|------|------|
| 层级 | L7,基于 HTTP / HTTPS |
| 路由依据 | 路径(`/api/*`)、Host header、HTTP header、查询参数、IP |
| 目标类型 | EC2、IP、Lambda、容器 |
| 高级 feature | WebSocket、HTTP/2、Cognito 集成、redirect/fixed-response、用户认证(OIDC / SAML) |
| **关键考点** | 题目说 "**path-based routing**" / "**host-based routing**" / "**HTTP header**" / "**Lambda 作为目标**" → **ALB** |

### NLB(Network Load Balancer)

| 特性 | 说明 |
|------|------|
| 层级 | L4,TCP / UDP / TLS |
| 性能 | **每秒数百万请求**,毫秒级延迟 |
| **静态 IP** | ✅ **每个 AZ 一个静态 IP**(或 Elastic IP) |
| 保留客户端 IP | ✅(自带) |
| 关键考点 | 题目说 "**极致 TCP 吞吐 / 静态 IP / UDP / 低延迟**" → **NLB** |

### GWLB(Gateway Load Balancer)

- L3 透明转发
- **唯一用途**:接入第三方安全设备(防火墙、IDS/IPS、深度包检测) — 用 GENEVE 协议封装,把流量"穿"过虚拟设备再返回
- 题目说 "**第三方网络安全设备 / inline traffic inspection**" → **GWLB**

### CLB(Classic Load Balancer)

- 旧版,新设计不要用 — 但**有些老题**还会出现

### 一张选型表

| 需求 | 选 |
|------|-----|
| Web 应用 + 路径路由 | ALB |
| 微服务 + gRPC + Lambda | ALB |
| 游戏 / VoIP / IoT(UDP) | NLB |
| 需要静态 IP / Elastic IP | NLB |
| 极端吞吐量 | NLB |
| 跨账号 / 跨 VPC 接入第三方防火墙 | GWLB |

## 二、Auto Scaling Group(ASG)

### Scaling 策略对比

| 策略 | 描述 | 何时用 |
|------|------|--------|
| **Target Tracking** | 设定目标值(如 CPU 50%),自动调 | **首选**;最简单 |
| **Step Scaling** | 分阶段(CPU 60%→+1,80%→+3) | 想精细控制响应曲线 |
| **Simple Scaling** | 单触发 | 老版,基本不用 |
| **Scheduled Scaling** | 按时间表(每周一 9 点 +5) | **可预测的周期负载** |
| **Predictive Scaling** | ML 学习历史,提前 scale | 历史规律明显的应用 |

### ASG 健康检查

- **EC2 检查**(默认)— 实例状态正常即可
- **ELB 检查** — ALB/NLB 健康检查失败 → ASG 替换 — **生产推荐**
- **Cooldown** — 防止抖动,默认 300 秒

### 题目套路

| 题目说 | 答案 |
|--------|------|
| "周一上午流量飙升,可预测" | **Scheduled Scaling** |
| "应用挂了但实例 OK,ASG 不替换" | 把健康检查源切换为 **ELB**,不是 EC2 |
| "扩容跟得上突发流量" | **Target Tracking** + **Warm Pool**(预热实例) |
| "无服务器扩容" | **Lambda** 自动并发 / **Fargate** |

## 三、Route 53 — 不只是 DNS

### 七种路由策略

| 策略 | 一句话 | 何时考 |
|------|--------|--------|
| **Simple** | 1 个或多个 IP,客户端轮询 | 最基础 |
| **Weighted** | 按权重(如 90/10) | **蓝绿 / 灰度发布** |
| **Latency-based** | 路由到延迟最低的 Region | **全球应用就近访问** |
| **Geolocation** | 按用户**地理位置** | 合规、本地化内容 |
| **Geoproximity**(Traffic Flow) | 按地理坐标,**可加 bias** | 需用 Traffic Flow,复杂 |
| **Failover** | 主备切换(配合健康检查) | DR / 灾备 |
| **Multi-Value Answer** | 返回多个健康 IP | DNS 级简单负载均衡 |

### 关键考点辨析

| 题目说 | 答案 |
|--------|------|
| "用户从最近的 Region 拿数据" | **Latency-based** |
| "中国用户去 cn 站,日本用户去 jp 站" | **Geolocation** |
| "灰度 / canary,10% 流量到新版本" | **Weighted**(10/90) |
| "主 Region 挂了切到备 Region" | **Failover** + Route 53 健康检查 |
| "蓝绿无停机切换" | **Weighted** 把权重从 100/0 慢慢切到 0/100 |

### Alias 记录 vs CNAME

| Alias(AWS 专有) | CNAME |
|------------------|-------|
| **可指向根域**(apex,如 example.com) | ❌ 只能指向子域 |
| **指向 AWS 资源**(ALB、CloudFront、S3 网站、API GW) | 任意 DNS |
| **免费查询** | 收费 |

**记住**:`example.com` 指向 ALB → 必须 **Alias**(CNAME 不允许 root 域)。

## 四、CloudFront — CDN + 边缘安全

### CloudFront 工作流

```
用户 → Edge Location(缓存命中?)
           │
       命中 → 直接返回
       未命中 ↓
       Regional Edge Cache(命中?)
           │
       未命中 ↓
       Origin(S3 / ALB / EC2 / 自定义)
```

### 关键概念

| 概念 | 一句话 |
|------|--------|
| **OAC**(Origin Access Control)| 让 S3 桶**只允许 CloudFront 访问**(替代旧的 OAI) |
| **Signed URL / Signed Cookie** | 限时、受限访问私有内容 |
| **Lambda@Edge** | 在边缘节点跑 Lambda(请求 / 响应改写) |
| **CloudFront Functions** | 比 Lambda@Edge 更便宜、更轻,仅 viewer request/response |
| **Geo Restriction** | 按国家放行 / 拒绝 |
| **Field-Level Encryption** | 表单字段在边缘加密,后端拿到密文 |

### 题目套路

| 题目说 | 答案 |
|--------|------|
| "全球静态资源加速 + S3 私有" | **CloudFront + OAC** + S3 桶策略只接受 OAC |
| "动态请求加速 / API 全球加速 + 静态 IP" | **Global Accelerator**(不是 CloudFront) |
| "在 viewer request 改 Host / 重定向 / A-B test" | **CloudFront Functions** |
| "在请求里查 DB / 调 API" | **Lambda@Edge** |
| "限制只允许某些国家访问" | **CloudFront Geo Restriction** |
| "付费视频只给付费用户访问" | **Signed URL / Signed Cookie** |

### CloudFront vs Global Accelerator — 易混

| 维度 | CloudFront | Global Accelerator |
|------|------------|--------------------|
| 主要场景 | **缓存静态内容**(也支持动态) | **加速动态 / TCP UDP** |
| 协议 | HTTP/HTTPS | TCP/UDP(任意) |
| IP | 域名 | **2 个 anycast 静态 IP** |
| 后端切换 | 取决于配置 | **秒级 failover**,健康检查 |
| 适合 | 视频、网站、API 网关 | 游戏、VoIP、IoT、SaaS 多 Region |

## 五、VPC 进阶 — 互联与流量分析

### 5.1 VPC 之间互通 — 矩阵

| 方案 | 传递性 | 跨账号 | 跨 Region | 成本 |
|------|--------|--------|-----------|------|
| **VPC Peering** | ❌ 不传递(A↔B、B↔C ≠ A↔C) | ✅ | ✅ | 数据 |
| **Transit Gateway** | ✅ **中心辐射,可传递** | ✅ | ✅(TGW Peering) | 小时 + 数据 |
| **VPC Endpoint Service / PrivateLink** | — | ✅ | ❌(同 Region) | 小时 + 数据 |
| **AWS Cloud WAN** | ✅ 全球骨干 | ✅ | ✅ | 复杂场景 |

### 5.2 与本地数据中心连接

```
公司 IDC ─────────┬──── Site-to-Site VPN(几小时上线,加密,带宽看 ISP)
                  │
                  ├──── Direct Connect(数周上线,1/10/100 Gbps 专线,不加密)
                  │
                  └──── DX + VPN(专线 + 加密 = 高速 + 合规)
```

| 需求 | 选 |
|------|-----|
| 快速、加密、低成本 | **Site-to-Site VPN** |
| 高带宽、低延迟、稳定 | **Direct Connect** |
| Direct Connect 也要**加密** | **DX + VPN over DX** |
| Direct Connect **抗故障**(双线) | **DX with LAG** 或 **2 个 DX location** |
| 公司端口数有限,连多个 VPC | **DX Gateway**(一个 DX 对接 TGW 或多 VPGW) |

### 5.3 高级流量分析

| 服务 | 一句话 |
|------|--------|
| **VPC Flow Logs** | 每条 5-tuple 流量记录,送到 S3 / CloudWatch / Kinesis |
| **Traffic Mirroring** | **复制**网络包到分析工具(IDS) |
| **Reachability Analyzer** | 给两个 ENI,告诉你能不能通,卡哪一步 |
| **Network Access Analyzer** | 找出**违反预期**的可达路径 |

题目说"调试 EC2 连不上 RDS,要排查路由 / SG / NACL" → **VPC Reachability Analyzer**。
